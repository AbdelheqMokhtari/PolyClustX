# Extend the documentation

The site uses Sphinx, MyST Markdown and `sphinx_rtd_theme`. Guides use short,
task-oriented pages. Add a page to the appropriate toctree in `docs/index.rst`;
avoid maintaining a second navigation structure.

```bash
pip install -e ".[docs]"
sphinx-build -W --keep-going -b html docs docs/_build/html
python -m http.server 8000 --directory docs/_build/html --bind 127.0.0.1
```

Catalog tables are generated by `docs/_ext/pymv_catalog.py` from the actual
registries. Update source metadata rather than copying lists into documentation.
API pages use autodoc. Add runnable offline examples and tests when introducing
new workflows; the text should describe only implemented capabilities.

The shared logo is `src/pymv/assets/logo.png`. Documentation colors live in
`docs/_static/custom.css`, and workbench colors in
`src/pymv/assets/workbench.css`. Keep burgundy as an accent, with slate text and
light neutral surfaces. Avoid embedding text in the symbol.

Read the Docs configuration is in `.readthedocs.yaml`. The docs CI workflow builds
HTML without deploying. Deployment requires the repository owner to connect a
hosting project; branch work does not automatically publish or merge anything.
