# Extend the documentation

The site uses Sphinx, MyST Markdown and `sphinx_rtd_theme`. Guides use short,
task-oriented pages. Add a page to the appropriate toctree in `docs/index.rst`;
avoid maintaining a second navigation structure.

```bash
make docs-build
make docs-serve
```

Catalog tables are generated by `docs/_ext/polyclustx_catalog.py` from the actual
registries. Update source metadata rather than copying lists into documentation.
API pages use autodoc. Add runnable offline examples and tests when introducing
new workflows; the text should describe only implemented capabilities.

## Which file should I edit?

| Contribution | Documentation location |
| --- | --- |
| New model or changed assumptions | `docs/background/algorithms.md`, registry metadata and `docs/api/models.rst` |
| New dataset or representation | `DatasetSpec` / `VARIANTS` in `src/polyclustx/data/registry.py`; generated catalog needs no manual row |
| File format or alignment change | `docs/user_guide/data.md` with a small loading example |
| Interface workflow | `docs/user_guide/workbench.md`, plus the README if launch/install changes |
| New public function | Relevant `docs/api/*.rst` page and a task-oriented guide |
| New tutorial | `examples/`, `docs/user_guide/examples.rst`, tests, and a toctree entry if it is a new page |

Write for someone installing the published package: avoid branch status,
maintainer-only instructions and claims about unimplemented capabilities.

## Interface screenshots

The guide contains `polyclustx-screenshot` references. Place your captures under
`docs/_static/screenshots/` using these filenames:

- `interface-overview.png`
- `dataset-details.png`
- `dataset-preprocessing.png`
- `hyperparameter-search.png`
- `results-visualizations.png`
- `export-center.png`

This image directory is ignored by Git. Add a matching PNG and run
`make docs-build` to include it. Missing captures are omitted, so readers never
see authoring placeholders. Use small synthetic data and omit personal paths
or IDs. Do not force-add screenshot files to Git. Ignored files are not sent to
GitHub: any build that needs the images must have them in this directory before
Sphinx starts.

Test the site with `sphinx-build -W --keep-going -b html docs docs/_build/html`.
Warnings fail CI, including broken references. The HTML preview artifact on
each pull request lets reviewers inspect the generated pages without deploying.

The shared logo is `src/polyclustx/display/assets/logo.png`. Change palette values
only in `src/polyclustx/brand.py`: both Sphinx and the interface consume these
tokens. Layout rules live in `docs/_static/custom.css` and
`src/polyclustx/display/theme.py`. Keep light surfaces, readable text and restrained
indigo accents. See [brand assets and provenance](https://github.com/AbdelheqMokhtari/PolyClustX/blob/develop/BRANDING.md) before modifying
logos. Keep institutional marks unchanged and separate from the project logo.
